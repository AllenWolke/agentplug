# SDK 执行世代事件序号区间

协议标识：`sdk-event-range/v1`。本协议用于三语言 SDK 的本地事件投影，平台 SQL 执行事件仍使用自己的持久序号。

## 分配规则

已验签执行上下文中的 `execution_revision` 为 `r`，取值为 `1 <= r <= 2^33`。每个修订保留 `W = 2^20` 的区间，基数 `B = (r - 1) * W`。该世代实际追加的事件只能使用 `B + 1` 至 `B + W - 1`，最大序号为 `2^53 - 1`。

基数和未使用序号只是分配空间，不代表曾发生事件。SDK 不创建占位事件、历史正文、历史输出或虚构的最后事件序号。第一条实际 accepted 事件使用 `B + 1`。客户端按 `seq > after_seq` 读取，不假定两个实际事件的序号连续，因此新进程的较新执行世代不会重新从 1 开始而被旧游标遮挡。

修订必须来自 SDK 已验证的执行身份，不能取自业务 input、浏览器参数或未经验证的恢复引用。该区间不是恢复授权，也不证明旧进程已经退出。

Agent 事件请求游标 `after_seq` 统一为严格整数 `0..2^53-1`，实际输出 `seq` 为 `1..2^53-1`。越界请求在签名、Store 读取和 HTTP/gRPC 出站前拒绝，不能作为成功的空结果；自定义 Store 的越界事件也必须在披露前拒绝。前端保留十进制字符串游标，校验事件正文中的安全整数 seq 与 SSE id 一致。protobuf 字段保持 uint64，数值上限由各实现的应用边界执行，不更换消息类型或字段编号。平台 SQL 历史的独立 uint64 游标不受该 Agent 上限影响。

## 生命周期 SPI

可选的 GenerationRunStore 接口接收 Scope、幂等键和执行修订三个非秘密参数：

- StartGeneration：原子创建运行和第一条 accepted 事件；同 Scope、幂等键和修订的回放不追加事件；冲突拒绝。
- ResumeGeneration：只对真实 waiting 投影生效；新修订严格递增，新基数不能小于旧投影的实际最后事件序号；原子切换区间及追加 started 事件。已有真实事件保留。

Go、Python、Java 方法按各语言命名习惯实现。直接调用原有 StartRun/Resume 的兼容语义保留；不支持该 SPI 的自定义 Store 不获得事件跨世代保证。后续通用故障恢复必须要求明确支持所需投影 SPI，不能通过兼容 StartRun 绕过恢复准入。

ResumeGeneration 对非 waiting 状态一律拒绝。请求回放由 SDK 已登记的同代执行身份处理，不能在缺少本地执行身份时把 Store 内已有 running 记录当作可以重新启动业务的证明。Scope 比较沿现有稳定身份规则：TraceID 和当前授权版本可以变化，租户、主体、Agent、安装、会话和父运行等隔离字段不能变化。

只有原本允许零执行修订的兼容入口继续其既有行为，不推断零修订为 1，也不分配新事件区间。Python 监督登记器原本要求非零修订，保持这一要求，不为兼容放宽取消或监督身份。非零修订超过区间协议上限必须拒绝，不降级至旧序号模式。

AdoptWaiting 导入的 `last_event_seq` 仍来自原已退出处理器的实际交接收据，不能改成新基数。当随后 ResumeGeneration 切换到新世代时，下一条实际事件为 `max(当前区间基数, 已有真实最后序号) + 1`，空缺不表示丢失历史被补造。

## 原子性与边界

所有事件追加及关联状态、输出、错误、取消信号修改前，必须在同一 Store 锁内检查序号额度。耗尽时拒绝，不允许跨区间、溢出或先修改状态再返回错误。同代回放不能重新分配基数。超过最大修订明确拒绝。

区间宽度只是序号分配上限，不是内存、CPU、并发、输出字节或进程资源配额。这些限制仍由运行时策略和执行控制器负责。内存 Store 仍只用于开发，事件正文不因进程重启而恢复；持久平台历史仍从平台执行历史接口读取。

## 故障恢复范围

普通 OS 退出恢复还需要已提交停止来源、当前公共 State 检查点、原业务输入、当前权限与新租约核验，以及对已派发模型/工具的只读回执查询。事件区间不能替代这些步骤。批准写工具恢复继续要求原批准与可信交接，不因区间可分配而跳过确认。

本协议的源码接线与总体场景验收分别记录在任务3进展文档；没有部署与实际跨进程证据时不能声称完整 Recovery 已验收。
