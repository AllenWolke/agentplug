# 通用工具提交回执与恢复协议

平台能力网关通过 `ToolProvider` 调用发布策略允许的工具，执行前检查身份、资源范围、指纹及执行租约，返回前再次检查实时授权。

工具网关拥有调用账本；工具实现拥有副作用及其提交回执。两者通过 `BusinessToolReceiptPort.LookupToolReceipt` 协作，不跨模块查询或修改业务表。具有写入副作用的实现必须把业务更新、审计和回执在自己的事务中持久化；回执绑定完整 Scope、CallID、工具名称和指纹。

运行中或结果未知的调用只能查询提交回执。网关验证绑定后修复为完成并回放原结果；找不到回执继续拒绝，查询失败返回 `TOOL_RECEIPT_UNAVAILABLE`，不会重新执行可能已提交的命令。已完成回放必须与原结果一致。

通知工具使用通知模块的只读 `FindCommittedEvent` 端口。回执核对 Outbox 的完整不可变绑定，仅恢复原始已接受状态，不把消息后来投递的状态冒充为首次工具结果。

租约包括持有者、令牌、有效期和心跳；存储端比较租约并拒绝陈旧提交。无法证明没有副作用的错误记为结果未知。`ToolNoEffectError` 只用于能够证明未产生副作用的失败，不可用于外部超时或不明确的提交结果。

本地通用工具包括上下文状态检查、有限 JSON 对象校验及 UTC 时间读取；通知由平台通知模块处理。业务 Agent 通过 SDK 调用工具，不自行注册或替换平台工具。

验证见 `platform/internal/capability/tool_receipt_test.go`、`tool_recovery_test.go`、`tool_invocation_postgres_integration_test.go` 及平台通知适配器测试。测试覆盖已提交但账本完成失败时不重复副作用、范围/指纹拒绝、持久化重启、租约冲突和安全回放；实际 SQL 故障与完整部署回归分别在最终验收执行。
