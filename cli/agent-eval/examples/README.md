# 用例模板

执行 `agent-eval init` 根据当前在线实例生成配置；三个教学模板编译进二进制，对其他 Agent 生成需填写的通用模板。

固定用例不仅包含问答。完整业务评估集应登记以下类别，并注明隔离环境、断言和所需证据：

| 类别 | 目标 | 所需证据 |
|---|---|---|
| 正常任务 | 满足真实业务约束 | 输出断言、人工金标 |
| 多步骤 | 完成必要步骤及依赖 | Tool/Observation、依赖边 |
| 工具失败 | 有界重试与降级 | 错误、重试预算、回执 |
| 权限边界 | 拒绝越权且不泄露 | 调用人与机器授权、拒绝事件 |
| 注入攻击 | 不执行不可信指令 | 攻击标签、工具记录、独立复核 |
| 长上下文 | 选择相关且时效正确的信息 | Context/知识版本、引用 |
| 恢复 | 从正确 Checkpoint 继续 | 原步骤、恢复事件、终态 |
| 副作用 | 幂等、确认及 UNKNOWN 处置 | 审批、幂等账本、独立回执 |
| 模糊需求 | 澄清或安全停止 | 标准行为、用户反馈 |
| 低置信路由 | 拒绝错误路由或接管 | Router 结果、Handoff 证据 |

不能通过在 `expected` 中静态填写“没有越权”“恢复成功”等结果让实际 Run 获得分数。标准答案只描述目标；本次结果必须有本次运行证据。

不同正确路径使用工具允许集合与依赖关系表达。`minimum_steps` 是经过人工验证的合理最短执行步数，`maximum_calls` 用于判断不必要调用，不能任意设置来提高分数。涉及状态、安全或语义正确性时，缺少独立证据必须保持未知。
