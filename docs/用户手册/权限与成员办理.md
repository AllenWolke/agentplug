# 权限与成员办理

业务用户申请所需能力，管理员核对用途、范围、期限和实际差异后办理。批准提交成功以后，还需要目标用户完成实际使用核验。

## 公司、部门与 Agent

一个账号属于一个公司工作空间，可加入该公司多个部门。这里的“应用”指可使用的 Agent。技术详情中的 Application 是历史接入与策略容器，不等于一家公司，也不等于用户获得了某个 Agent 的权限。

默认管理流程由公司管理员、部门管理员和部门用户完成。权限管理员作为可选的集中办理角色保留，只有公司明确委托后才能办理对应事项。管理身份不会自动开通 Agent 运行权限。

新版公司管理员是专门任命的 `tenant_admin` 第 2 版角色，只管理账号所属公司。旧第 1 版租户管理员保留原有能力；已有全平台管理员也不会自动降级。`system.admin` 是账号名，其实际权限以“我的管理范围”显示的有效角色为准。

## 任命公司管理员

1. 由具备管理员任命权限的全平台管理员打开“用户主体管理”，选择本公司账号，再打开“管理员任命”。
2. 选择“公司管理员”。公司范围由目标账号确定，无需手填公司编号；设置期限并填写任命原因。
3. 如要将旧全平台管理员改为公司管理员，明确勾选需要撤销的原身份。仅新增角色不会收回旧权限。
4. 预览变更，完成当前认证方式要求的再次认证，再提交。角色新增和勾选的撤销在同一事务内办理。
5. 刷新目标账号，检查“我的管理范围”、部门管理和用户管理入口。管理身份不能给自己申请或增加业务权限。

撤销旧全平台管理员前，必须保留另一名有效、长期且能够登录的全平台管理员。系统会阻止撤销最后一个恢复入口。公司管理员不能任命公司管理员或全平台管理员，也不能停用这些受保护账号。

这些功能需要部署匹配当前数据库结构的前后端。升级数据库会补齐结构及基础使用角色，保留旧授权；已有公司角色和部门使用上限须分别预览、确认迁移。新部门默认没有开通 Agent。

## 创建部门并设置成员身份

1. `system.admin` 打开“部门管理”，填写部门名称。所属公司自动确定，部门编码可以留空。
2. 创建成功后点击“添加部门成员”，或在部门列表点击“成员与身份”。
3. 选择本公司的账号，打开“成员关系”。目标部门会预先选中，也可选择其他有权管理的部门。
4. 在“部门身份”选择“部门用户”或“部门管理员”。编辑已有成员时，默认保持现有身份；改为部门用户会在预览中列出将撤销的部门管理员身份。
5. 填写期限与原因，预览成员和岗位变化，再确认提交。加入部门及新任命的部门管理员身份使用同一份变更原子提交。
6. 再开通该部门获准的 Agent。部门管理员添加成员和分配 Agent 的办理范围由公司限定；不能任命其他管理员或移除同级管理员。

部门可以在没有 Agent 时先准备成员。创建部门会同时准备内部管理接入范围，供管理员进入该部门办理；这不会安装 Agent，也不会自动给任何用户开通使用权限。部门用户首先是普通成员，实际使用 Agent 仍需明确岗位和资源授权。

## 我需要申请使用权限

1. 确认当前工作空间与业务任务一致。
2. 在“我的身份与权限”查看岗位、可用助手、资源和期限。
3. 打开需要授权的助手，填写使用理由。若从“我的权限申请”新建，选择正确范围、岗位及助手操作。
4. 对普通助手使用，可以点击“选择基础使用 5 项”：查看、运行、取消、查看本人历史、继续会话。它不会选择分享、导出等额外能力，也不会替你取得岗位或依赖资源。
5. 提交后在“我的权限申请”查看办理结果。受理或批准部分事项不等于整份申请全部获批。
6. 获批后刷新权限，再在原应用实际使用。

## 为一位同事开通

办理入口是“用户主体管理”，需要管理该账号和对应范围的权限。

1. 核对公司和目标部门，找到同事账号，检查账号状态。
2. 先配置部门归属与部门身份；成员关系仅决定归属。
3. 打开“身份与权限”，选择岗位预设、组织范围、对应助手和期限，填写原因。
4. 预览新增与撤销的差异，确认账号、范围、数据权限、期限后提交。
5. 如果助手依赖模型、知识、工具、技能等资源，展开“高级设置：独立资源与精细权限”，核验并补齐明确资源授权。人员和机器的资源权分别检查。
6. 让同事刷新权限并实际完成一个目标任务。岗位配置成功、机器绑定成功或部署健康，都不能代替这个步骤。

“基础岗位预设”与“助手和依赖资源”不同；不要为解决一次拒绝而直接授予全平台范围或长期权限。已有明确拒绝和其他来源的权限也要保留核对。

已有授权默认折叠，按 Agent 或依赖资源分组。需要收回权限时再展开“调整已有授权”；“选择本组允许项”只选该组允许记录，拒绝规则需逐项明确选择。每条授权及其来源仍能单独核对。

管理账号不显示个人新建权限申请；后端同时拒绝管理员个人新申请和自增业务授权。已有申请记录仍可查看。需要业务使用时，由其他有权人员为对应业务账号办理。

公司管理员在部门的“可用 Agent”配置使用上限，部门管理员在该上限内给实际成员开通基础使用。减少上限会限制已有个人授权的后续受保护操作；重新开通不会自动恢复已失效的旧来源授权。其他有效来源、明确拒绝和取消资格仍按服务器规则核验。预览中的受限人数是授权记录层面的影响，不能当作正在运行的任务数，也不表示能够撤回已经发生的外部操作。详细操作见[公司与部门 Agent 授权指南](../开发者指南/公司与部门Agent授权指南.md)。

## 办理一份权限申请

进入“角色与资源审批”，核对申请人、目标应用、业务理由、申请内容与期限。快捷按钮可选择申请中已有的基础使用事项，未申请的事项不会被加入。

未勾选事项将被拒绝，全部不勾选表示拒绝整份申请。分享、导出和其他敏感能力仍需单独判断。点击预览，核对每项将被批准还是拒绝，填写说明后提交。版本冲突时重新读取与预览，不能继续提交过期差异。

## 给多人分配部门或开通 Agent

1. 在“用户主体管理”勾选本公司其他有效账号。可跨页选择，每批最多 50 人；本页全选只选择当前页。
2. 选择“分配部门与身份”，共同配置部门和部门用户/管理员；只有公司管理员可任命部门管理员。或选择“开通 Agent 使用”，配置共同部门和公司批准的 Agent。
3. 开通使用时核对基础会话及该 Agent 的模型、知识、工具等依赖摘要。有成员管理权时可明确选择同步加入未入部门的用户；已有成员和期限保持不变。
4. 填写原因和可选到期时间，预览每人新增、收回或不能办理的事项。确认后逐人检查结果，预览未通过的项目不会办理。
5. 分享、导出、内容修改、跨 Agent 委派及其他高级能力，仍从单人“身份与权限”按需配置；机器授权单独核验。

基础使用组合固定预览时的发布版本和依赖，配置变更后需重新预览。每人单独提交，某人失败不会撤销其他已完成项目，也不会重复办理已成功项目。

## 批量办理申请与中断恢复

在“角色与资源审批”勾选待办，选择“核对所选申请”，明确选择每份申请批准的事项或整份拒绝，填写共同原因后预览。未选事项不获批；同一用户的多份申请分批办理，后续重新预览。

中断或结果未知时选择“查询原批次”。确认状态后再明确“继续未办理项”或“停止未办理项”；停止保留已完成的权限。重新打开页面和切换语言只读取原结果，不自动重发权限。无待办并核对结果后，才选择“已查看结果，准备下一批”。

## 哪些操作会产生影响

| 操作 | 影响 |
| --- | --- |
| 预览授权差异 | 核对计划，不产生实际权限 |
| 确认提交权限 | 产生批准范围内的岗位、资源或撤销事实 |
| 任命管理员 | 取得对应管理身份；明确委托与实际资源范围仍需核对 |
| 撤销成员关系或授权 | 该来源的访问将失效，相关角色和资源可能随之撤销，以预览为准 |
| 指派业务任务 | 限定指派事项的操作范围；用户仍需对应岗位与助手资源权限 |
| 绑定机器与安装 | 建立工作负载关联；不会自动给机器授予全部资源权限 |
| 分享、导出、代码执行 | 具有额外数据或执行影响，遵守独立授权与审批规则 |

提交结果不明确时，应查询原申请或当前事实。不要把网络中断自动理解为没有生效。
