# 管理员与开发者操作指南

先确定公司工作空间和部门。用户使用的应用指 Agent；接入和发布页面中的技术应用是部署及策略容器。菜单依据当前权限显示；管理能力、业务使用权和机器资源权分别授予。

## 创建部门并配置成员

1. `system.admin` 在“部门管理”填写部门名称并创建。所属公司固定为当前公司，部门编码可以留空。
2. 点击该部门的“成员与身份”，找到本公司用户并打开“成员关系”。
3. 确认部门，选择“部门用户”或“部门管理员”，填写期限和办理原因。
4. 点击“预览成员与权限差异”，核对新增身份及撤销事项，再确认提交。成员关系和部门身份在同一事务中保存。
5. 加入部门后，另行开通获准 Agent。部门管理员可添加本公司成员，并在公司批准的部门 Agent 上限内分配基础使用权限；不能任命或移除同级管理员、提高部门上限或授予未获准的敏感操作。

没有安装 Agent 的部门也能先配置成员。创建部门不会自动添加用户或开通 Agent。公司管理员在部门的“可用 Agent”配置使用上限；随后可在用户列表勾选多人，选择“分配部门与身份”或“开通 Agent 使用”，预览并逐人核对结果。详见[权限与成员办理](权限与成员办理.md)。

## 接入一个助手

1. 阅读[三语言 SDK 业务 Agent 开发指南](../开发者指南/三语言SDK业务Agent开发指南.md)，选择模板或接入已有服务。
2. 在助手目录登记定义与不可变版本，填写真实制品摘要和输入输出协议。登记不等于发布。
3. 完成评测及独立审批，发布版本后安装到目标应用。
4. 配置目标版本的部署，由可信运行控制面报告对应部署就绪，再激活安装。
5. 准备完整运行配置：模型、提示词、工具、记忆、知识及运行策略；核对实际依赖版本，再发布运行快照。
6. 创建并绑定正确的机器身份，分别为人员与机器开通所需资源权限。
7. 使用目标账号完成一次真实任务，核对结果、来源、历史、计量和需要时的停止证明。

从空库创建完整示例请按[部署与授权指南](../开发者指南/业务Agent挂载与已有用户授权指南.md)执行。页面准备清单、离线请求计划、服务探活或原型状态都不是实际发布成功的证明。

## 配置模型

在“模型治理”中依次核对供应商、模型、不可变版本、部署、价格和访问策略。供应商字段使用服务端受管密钥引用；真实密钥不应放进页面、公开文档或 Git 仓库。

运维维护受信地址映射，测试并批准供应商与实际模型版本。价格应明确货币、计价单位和生效区间；内部配置价格不等于供应商账单。把批准的版本写入助手模型策略以后，仍需实际调用核验。

当前界面没有完整的全局预算与阈值告警管理流程。用量账本与任务结果可以提供事实核对，但不能因此宣称已具备完整成本运营能力。

## 办理待批准的工具操作

1. 在原任务中打开待批准操作，点击“核对待执行操作”，确认工具、目标和参数。隐藏或截断的参数应先向业务负责人核实。
2. 页面按当前登录方式验证身份：本地登录输入当前密码；企业统一登录会打开身份提供方窗口，验证当前账号，无需本地密码。
3. 点击“再次认证并批准此操作”。批准仅适用于本次核对的具体操作；如需执行，点击“继续运行”。
4. 执行前可以再次验证身份并撤销批准。撤销会阻止继续使用该批准；已经完成的业务操作按其业务撤销流程处理。

认证窗口关闭、取消或预览到期时，重新核对操作再办理；页面不会自动提交或改用本地密码。读取认证方式失败可点击“重新读取认证方式”。如企业统一登录提示再次认证未配置，联系平台管理员配置身份提供方。

验证身份不会增加权限。提交时仍检查当前账号、登录会话、任务、已发布策略、人员与机器资源权限，以及待执行操作的参数。另一个登录会话、已撤销权限或修改后的操作不能使用原认证凭证。继续运行结果无法确认时，先查看原任务状态，避免重复执行。

## 出现异常时

| 异常 | 核对顺序 |
| --- | --- |
| 无管理入口 | 当前身份能力、管理范围与明确委托 |
| 助手不可用 | 安装状态、对应版本部署、运行快照及六类策略 |
| 权限拒绝 | 人员成员/岗位、助手操作、依赖资源、机器绑定和授权、期限、拒绝规则 |
| 模型失败 | 受信供应商配置、实际模型版本、部署状态与访问策略 |
| 知识无结果 | 知识源、索引版本、ACL、知识策略与实际检索事实 |
| 管理提交冲突 | 当前修订与计划期限；重新读取、预览差异 |
| 流式连接中断 | 原任务状态和运行历史；避免重新创建相同副作用任务 |

保留账号、目标应用、页面、操作时间、任务或追踪编号即可开始定位。不要通过扩大所有权限或取消独立审批来隐藏配置问题。
