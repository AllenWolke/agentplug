# AgentPlug user guide

[中文版](README.md)

Start with the task you want to complete. Check your company workspace and department after signing in, choose an available assistant and try one example. A company administrator may manage several departments within the same company. Connection scopes under **Advanced connection settings** are technical deployment scopes, not additional companies or departments.

| Task | Guide |
| --- | --- |
| Run an assistant and retrieve results | [Quick start](Quick-start.en.md) |
| Request access or enable a colleague | [Access and membership](Access-and-membership.en.md) |
| Connect agents, configure models and troubleshoot | [Administration and development](Administration.en.md) |
| Install the platform and develop your first agent | [Developer onboarding](../developer/en/README.md) |

Use **中文 / English** on the sign-in page or at the top right of the console. Your browser remembers the choice. Switching preserves the current page, form values and running task. Account names, resource IDs, business content and original agent answers are not translated. A newly inserted example follows your selected language.

Select **Getting started and help** in the sidebar for guidance appropriate to your permissions. A missing entry may mean your identity does not have access. Changing a display language never changes authorization.

Business users can run authorized agents, inspect results, read their own permitted history and request access. Administrators manage memberships, roles, grants, requests, agents, models and policies within their scope.

Administrators can select company accounts across pages to assign department roles or enable basic Agent access, and process several pending requests together. Each batch contains up to 50 items. Preview each person's effects before confirmation. Results are saved individually; after an interruption, query the original batch before explicitly continuing or stopping remaining items. Detailed resources, sharing and export remain separately configurable. See [Access and membership](Access-and-membership.en.md).

Availability depends on identity, membership, role, resource, data scope, expiry, policies and deployment. Administrative access does not automatically grant business usage. This guide describes implemented functions; demonstrations and service health do not prove production readiness.
