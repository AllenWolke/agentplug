# 快速开始

目标是完成一次你有权使用的助手任务，并知道结果在哪里找回。

## 完成第一次任务

1. 登录控制台，核对左侧公司工作空间与所在部门。一个账号属于一个公司，可加入多个部门；Agent 和数据权限仍需分别开通。
2. 打开“中台首页”，选择标记为“可使用”的助手。先阅读用途和当前状态。
3. 点击“填入示例”，或在业务表单中描述任务。示例运维助手需要服务名称和问题现象；文档助手需要问题；工单助手需要工单编号和摘要。
4. 点击“开始处理任务”。等待当前任务完成；仍在运行时不要反复提交同一个问题。
5. 核对结果和来源。需要了解运行编号、事件、版本或完整协议时，再展开对应详情。
6. 从“我的运行历史”找回本人获准的记录。页面是否允许继续、取消或其他操作，取决于当前权限和任务状态。

这三个示例的默认输入用于生成回答或草稿。工单草稿不等于已向客户发送消息，排查建议不等于已操作服务器。代码执行、跨助手协作或其他副作用能力需要对应策略、资源授权，敏感动作还需要单独批准。接入的其他助手应以其说明和实际协议为准。

高级使用者可以展开“高级输入”填写 JSON。切回业务表单需要 JSON 对象有效；不要仅为尝试功能添加自己不理解的执行开关。

## 看不见或无法使用助手

先确认工作空间，再查看“我的身份与权限”。提示需要授权时，可通过助手申请入口或“我的权限申请”提交使用理由。申请不会立即产生权限，批准后要刷新权限并核对每项结果。具体流程见[权限与成员办理](权限与成员办理.md)。

## 运行中断或没有结果

| 现象 | 下一步 |
| --- | --- |
| 显示仍在运行 | 等待并查询当前状态，避免重复提交 |
| 实时连接中断 | 控制台尝试读取后台状态；也可从状态查询或运行历史核对原任务 |
| 提交结果不明确 | 先找回原任务与编号，再决定是否需要重试；中断不代表后台失败 |
| 显示权限不足 | 核对当前应用、岗位、资源及有效期，联系该范围管理员 |
| 结果为空或失败 | 核对终态和完整记录，将页面、操作时间和追踪编号提供给负责人员 |
| 回答看起来正确但缺少依据 | 查看来源和限制，在用于实际业务前核对必要事实 |

公开反馈中不要提供密码、访问密钥或业务全文。管理员需要追踪编号和最小复现信息，不需要你的登录密码。
