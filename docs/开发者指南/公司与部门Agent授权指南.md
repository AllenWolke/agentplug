# 公司与部门 Agent 授权指南

适用于新版公司管理员、部门管理员和部门 Agent 范围。一个账号属于一家公司的工作空间，可加入其中多个部门；这里供业务人员使用的“应用”是 Agent。底层接入范围用于区分 Agent 的安装位置，不改变这层组织关系。

数据库升级和旧权限迁移是两件事。执行数据库升级会创建新结构，保留原有角色和授权；现有部门须由公司管理员预览并确认后启用部门范围限制。既有账号名不决定管理资格，以当前有效角色和委托为准。

## 谁负责什么

| 身份 | 可以做什么 | 不自动获得什么 |
| --- | --- | --- |
| 公司管理员 | 创建本公司部门、加入成员、指定部门管理员或用户、开通部门 Agent 范围、为其他合格管理员配置委托 | 其他公司的管理权、个人业务访问权 |
| 部门管理员 | 加入本公司用户到所管理部门，为部门成员分配公司开通的基础 Agent 使用权限 | 扩大部门 Agent 范围、任命其他管理员、开发/分享/导出等敏感权限 |
| 可选权限管理员 | 按明确委托办理指定范围内的授权和申请 | 未委托范围的管理权、个人自助扩权 |
| 部门用户 | 使用已分配、当前有效的 Agent 和资源 | 仅因加入公司或部门就使用全部 Agent |
| 平台恢复管理员 | 在受控任命流程中维护管理员和恢复入口 | 因管理资格直接访问业务内容 |

## 公司管理员：让部门具备可分配的 Agent

1. 确认公司工作空间，进入 **部门管理**。没有部门时先创建，随后通过 **成员与身份** 把本公司用户加入部门，指定部门管理员或部门用户。
2. 在目标部门选择 **可用 Agent**。新部门默认没有开通任何 Agent。
3. 找到 Agent 所在的接入范围，勾选需要开通的 Agent。默认选择日常运行、会话及所需资源操作；可展开调整操作和有效期。
4. 需要统一开通多个 Agent 时使用 **开通当前筛选结果**。它只作用于当前显示的筛选结果，保留已选 Agent 的自定义操作和其他接入范围的配置。未显示的后续页可通过 **下一页 Agent** 继续选择。
5. 填写调整原因并选择 **预览调整影响**。核对新增、收回或调整的 Agent，以及可能受限的账号、授权和旧模式账号。数字不代表正在运行的任务数。
6. 现有部门首次启用新规则时，核对旧账号迁移影响并明确确认。`legacy` / `shadow` 模式的账号不能绕过新部门限制，须完成账号权限迁移。
7. 按页面提示再次验证当前账号并提交。页面支持本地密码验证及已配置的 OIDC 再次认证，不接受浏览器自行声明的认证时间。

开通部门范围是使用上限；还需有效部门成员身份、岗位、具体 Agent/资源授权和数据范围。它不会把权限一次性赋给所有成员，也不会自动补齐运行配置或机器身份授权。

## 部门管理员：为成员分配使用权

1. 确认所管理部门，在 **用户主体管理** 查找同公司的账号。将用户加入部门；只加入公司不能代替加入目标部门。
2. 勾选需要开通的成员，选择 **开通 Agent 使用**，再选择共同部门和公司批准的 Agent。服务器依据该 Agent 的发布配置生成基础会话和依赖资源组合，不需要逐项填写技术编码。
3. 核对将开通的 Agent、模型、知识库、工具、记忆和技能摘要，填写原因并预览。分享、导出、内容修改、管理员身份和机器权限仍须按实际需要单独配置。
4. 公司批准未来开始的 Agent 可提前配置个人授权；实际使用仍要等开始时间。个人授权不能早于部门批准时间或晚于其到期时间，也不能超过办理人的有效管理期限。
5. 让目标用户刷新权限并实际运行一次。管理账号不能通过个人权限申请或给自己办理授权来扩大业务权限。

当前源码提供多人开通 Agent、部门成员与身份分配、申请审批的持久批次页面。既有部署需先执行数据库升级并部署匹配的前后端源码；只更新前端不能使新授权生效。数据库升级会补齐新的基础使用角色定义，保留旧角色、旧授权和成员关系，不会自动给任何用户增加权限。

## 管理身份与业务身份同时存在

部门管理员可同时属于多个部门。部门选择器显示服务器核准的管理范围，以及该账号独立加入的业务范围；切换到其他部门不会带入原部门的管理权。公司管理员、权限管理员仍从明确的管理范围选择部门。

切换部门优先选择已有有效岗位或明确成员关系对应的分组；同部门存在多个分组时，**Agent 分组** 控件直接显示。仅加入部门的业务用户，在个人申请中也可选择服务器核准的应用范围；名称用于阅读，提交仍使用原始范围编号。

管理员由其他有权办理人明确授予 Agent 使用权限后，首页和导航显示已获准使用的 Agent 及个人历史。管理身份不会自动授予业务使用权限，也不能借此为自己申请或办理新增权限。公司内的安装管理使用 **应用与 Agent**；全局 Agent 定义和发布入口仅向具备全局目录权限的账号开放。

## 多人开通 Agent 使用

1. 在 **用户主体管理** 勾选本公司其他有效账号，可跨页选择，每批最多 50 人，再选择 **开通 Agent 使用**。
2. 选择共同部门和 Agent，查看 **将开通的使用权限**。基础使用包括查看、运行、取消、查看及继续自己的会话；依赖资源只在该 Agent 范围内可用。多个安装位置按 **Agent 分组** 区分，完整编号和发布版本收在 **技术详情** 中。
3. 有成员管理权时，可明确勾选 **同步加入尚未加入该部门的用户**。已有成员关系和原期限保持不变；已到期、已撤销或尚未生效的成员须先单独调整。只有授权委托的权限管理员只能为已有有效成员办理。
4. 填写共同原因和可选到期时间，选择 **预览每人的变更**。现有权限和显式拒绝保留；部门上限、办理人资格、数据范围和有效期仍逐人检查。预览不通过的对象不会被部分开通依赖资源。
5. 核对影响并明确确认，按逐人状态查看结果。预览与执行固定同一个发布版本和依赖组合；发布配置发生变化时须重新核对。登记成功不等于所有人已获权，只有对应项目成功才完成个人开通。

此入口面向个人基础使用。跨 Agent 委派、开发、分享、导出及其他高级操作保留在单人 **身份与权限** 中，仍受原有审批规则约束；不会因开通基础使用而自动获批。中断后使用原批次查询、继续或停止剩余项，见下文。

## 多人分配部门与身份

1. 进入 **用户主体管理**，勾选本公司其他有效账号，可跨页选择，每批最多 50 人。**选择本页有效用户** 只影响本页，取消本页选择会保留其他页选择。
2. 选择 **分配部门与身份**，设置共同部门、身份、到期时间和原因。默认保留已有部门身份，新成员作为部门用户加入；只有有权公司管理员可选择将全部用户设为部门管理员或部门用户。
3. 留空到期时间会保留已有成员期限；填入时间才调整到期时间。原开始时间保留，新成员仍受办理人的管理期限约束。
4. 先查看每人的预览。岗位、资源或任务指派需要收回时会明确标出；**查看影响** 可展开完整信息。将已有部门管理员改为部门用户会收回其在目标部门的管理身份。
5. 核对后确认办理，按每人状态查看结果。预览未通过的项不会执行，某人失败不回滚其他已完成事项；加入部门本身不授予业务 Agent 权限。

用户列表默认展示身份与权限入口，其余单人功能收在 **更多操作** 中；成员关系、任务指派、管理员任命、委托和停用仍按当前权限显示。

## 批量审批申请

1. 在 **角色与资源审批** 勾选待办理申请，支持跨页选择，每批最多 50 份，再选择 **核对所选申请**。
2. 每批只处理同一公司的申请，每个用户保留一份；同一用户有多份申请时，处理后刷新并重新预览下一份，避免沿用已经变更的用户版本。
3. 选择 **按所选事项批准**，按申请勾选批准事项，或明确选择 **全部申请不批准**。批量批准每份至少勾选一项；需要整份拒绝的申请请另分一批。
4. **选择申请中的基础使用事项** 只选择申请已有的业务操作员及基础会话操作，独立资源、分享、导出与管理权限不自动选入。未勾选事项不获批准。
5. 填写共同原因并预览每份结果，确认后按结果核对；未批准事项与未成功办理事项分别以申请结果和批次状态为准。

批次结果列表默认显示账号、变更概要、状态及影响入口，完整细节按需展开。用户提出的申请原因、账号名和业务名称在切换中文/English时保持原文。

## 批次中断和继续

- 浏览器在登记前保存原批次编号；会话存储不可用时阻止登记，避免丢失结果查询入口。
- 断网后先选择 **查询原批次**。重新打开同一浏览器标签页会只读查询，语言切换也不会提交或继续权限操作。
- 查询确认尚有待办后，可明确选择 **继续未办理项**。已完成、失败或停止的项不会再次执行；失败项须重新核对后另行办理。
- **停止未办理项** 只影响剩余待办，保留此前成功变更。查看全部终态后选择 **已查看结果，准备下一批**。
- 原办理者失去当前范围资格后，不能读取或继续旧批次；新管理员须重新核对尚未完成的对象。

## 收回与恢复

收回 Agent 的部门范围后，后续受保护操作按最新上限校验。取消既有运行的原权限保留，仍需原有授权及运行对象校验；它不会给原本没有取消资格的用户新增权限。

重新开通 Agent **不会自动恢复部门管理员此前发出的已失效授权**，须明确重新分配。未受调整影响的其他 Agent、其他有效授权来源和显式拒绝保留。改变有效期也会使依赖原期限的部门授权需要重新办理。

这不表示撤回已完成的操作，或已经验收了所有在途 Agent 的硬停止。正在运行任务的恢复、停止与授权校验须分别验证。

## 提交后断网、冲突或找不到结果

- **结果不明确**：选择 **查询本次结果**，使用原请求编号查询。重新打开同一部门仍可继续查询，不会重复发送变更；查询暂时没有结果时稍后再查。
- **版本冲突**：使用 **刷新配置** 读取当前配置，再调整并重新预览。刷新会丢弃尚未提交的配置编辑。
- **再次认证失效**：重新核对预览并验证身份。提交成功的认证凭据不能再次用于另一项变更。
- **登录成功但不能运行**：检查部门开通范围、个人岗位和资源授权、有效期、运行配置及机器身份权限，向管理员提供追踪编号。

## 维护与验证

前端提供明显的 **中文 / English** 按钮；语言切换保留表单和预览，业务名称、输入和命令编码保持原文。

可使用以下固定范围命令验证真实 PostgreSQL 事务及选择器分页。它创建带归属标签的临时数据库容器，结束后清理，不连接项目业务数据库：

```powershell
python scripts/verify_public_knowledge_postgres.py --suite identity --department-agent-access --batch-id department-agent-local-check
python scripts/verify_public_knowledge_postgres.py --suite identity --permission-batches --batch-id permission-batches-local-check
python scripts/verify_public_knowledge_postgres.py --suite schema --batch-id department-schema-local-check
```

这些命令不代替真实登录账号、真实 Catalog/审计组合、在途业务运行和现有权限迁移验收。其他专用场景见[专用环境测试指南](专用环境测试指南.md)，界面文案维护见[中英文维护说明](前端中英文界面维护.md)。
