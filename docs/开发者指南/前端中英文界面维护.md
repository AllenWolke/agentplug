# 前端中英文界面维护

控制台目前支持 `zh-CN` 和 `en`。登录页、注册页及控制台提供中文 / English 按钮，浏览器记忆语言偏好。英文仅翻译界面，业务内容保持原文。

## 新增界面

在组件开头调用 `useLanguage()`，使显示名称、日期及动态文案随语言重新计算；不要在条件或循环中调用 Hook。用 `Localized` 包住组件返回的界面，完整中文消息及英文译文加入 `frontend/src/locales/en.js`。标题、按钮、标签、提示、空白状态、恢复说明和可访问名称均应覆盖。组件仍使用原有事件、表单及请求对象。

```jsx
import { Localized, useLanguage } from "../../components/Localization.jsx";

export function ExamplePage() {
  useLanguage();
  return <Localized><section><h2>页面标题</h2><button type="button">明确的动作</button></section></Localized>;
}
```

完整消息按精确词典键翻译，不对任意内容进行子串替换。动态消息使用 `{{0}}`、`{{1}}` 模板；使用 `interpolateUI` 传入参数，参数保持原文。内置角色或动作参数先经过受控显示函数，例如 `roleName` 和 `actionName`；实际命令仍提交原始代码。

```js
interpolateUI("{{0}}（编号 {{1}}）", [resourceTypeName(type), id]);
```

中文 JSX 相邻文字常没有空格，英文需要词间距。显示层只调整相邻原始文本，保留所有子节点数量、位置和键，避免语言切换导致表单重新挂载。不要以语言作为整个页面或表单的 `key`，也不要刷新页面来切换语言。

## 保护业务内容

用户输入、组织自定义名称、通知正文、模型回答、凭据、资源编号和 JSON 不是界面词典。用 `data-i18n-preserve` 明确保护业务区域；`pre`、`code`、`textarea` 及制品与回答渲染器也具有保护边界。新建业务内容组件可以标记 `Component.i18nOpaque = true`。字段 `value`、`defaultValue`、`name`、`id` 及事件不参与翻译。

```jsx
<p data-i18n-preserve>{notification.text}</p>
```

界面切换不能修改正在处理的原始输入、请求摘要、批准内容、运行编号或输出，不能重新获取审批凭据或重复提交任务。新点击“填入示例”可按当前语言生成一个新示例；已有草稿不得被覆盖。

后端未映射错误和自定义对象名称显示原文。不要为了消除中文而抹去错误含义或自动请求外部翻译服务。

## 验证

在 `frontend` 运行 `npm test` 和 `npm run build`，检查新增词典与模板、业务边界、原始动作值及构建结果。原有五个语言测试包含存储通知、未知业务文本、权限名称和命令值、示例与旧草稿，以及保持节点位置的英文间距。

浏览器至少检查中文和英文中的新增页面、登录按钮、长文本及手机宽度。切换前填写受控字段和原生字段，切换后确认内容、选项值、焦点和页面保留；任务运行时切换只能继续同一个运行。公开手册的中文版和英文版需与真实入口同步。
