# 专用环境测试指南

平台常规 Go 回归包含显式启用的集成测试：专用补偿数据库、Python 通信、权限规模、平台进程重启和真实模型调用。`go test` 成功但存在 `SKIP` 时，应继续执行对应专项；跳过不算验证通过。

以下命令从仓库根目录执行。需要 Docker Desktop、Go、Python、已下载的 Go 模块及测试所用镜像；数据库脚本创建新的隔离容器，不连接正在运行的开发数据库。所有命令使用新的 `--batch-id`，拒绝覆盖同名验收记录。

## 数据库与权限规模

先生成常规平台回归记录，再按其中完整包名和测试名执行专用补偿用例：

```powershell
python scripts/verify_public_knowledge_postgres.py --suite platform-all-go --batch-id baseline
python scripts/verify_dedicated_postgres_tests.py --inventory "docs/新增需求/github作品改造/T3-11-平台全量Go隔离PostgreSQL测试实际验证-baseline.json" --batch-id dedicated
python scripts/verify_public_knowledge_postgres.py --suite scale --batch-id dedicated
```

专用补偿脚本针对当前基线的 66 个跳过事件，包括子用例；每个模块使用一个独立数据库，全部指定事件必须实际 `PASS`。原清单发生变化时脚本明确拒绝，需要审阅和更新验收范围。它验证真实 SQL 事务、补偿幂等、停止事实约束、并发覆盖保护、索引撤销及通知收件箱；其测试权限和停止事实夹具不代表实际部署 Agent 的完整停止证明。

规模用例生成 10,000 个额外用户及 100,000 条绑定/授权，检查分页、权限解释和并发请求。脚本负责清理本轮带所有权标签的临时容器和生成的凭据。

## Go 与 Python 真实通信

当前 Python 环境须能导入 `grpc`、`google.protobuf`、`fastapi`、`uvicorn` 和 `cryptography`。SDK 声明见 [pyproject.toml](../../sdk/python/pyproject.toml)。

```powershell
python -m pip install -e "./sdk/python[grpc,asgi]" fastapi
python scripts/verify_optional_transport_and_models.py --suite interop --batch-id dedicated
```

专项实际启动一次性 Python 子进程，验证 Go 到 Python 的 gRPC 协议及真实 TCP 请求取消。依赖缺失、进程启动失败、指定事件未执行或再次跳过均判为未通过，不会以环境缺失代替通过。

## 真实平台进程重启

```powershell
python scripts/verify_public_knowledge_postgres.py --suite process --evaluation-restart --batch-id dedicated
```

专项编译带 race detector 的 Linux 平台程序并实际启动、停止、重启。平台停止期间直接运行原始 `TestSeedPlatformProcessRestartRun`，新进程必须从 PostgreSQL 接管其过期租约。刻意不完整的发布快照预期终结为 `SNAPSHOT_INVALID`，同时要求尝试次数增加、版本推进及终结后租约删除。这是恢复与安全拒绝验证，成功的业务评测应另行验收。

## 真实模型调用

该专项发送 4 个小型付费供应商请求，验证文本生成、两轮原生 Function Calling 及一个 Embedding 批次。应由操作者显式启用，并提供自己的私密凭据；不要将 `providers.json` 或密钥提交到 GitHub。

```powershell
python scripts/verify_optional_transport_and_models.py --suite models --model-metadata ".local-secrets/model-providers/runtime-mounts/providers.json" --batch-id dedicated
```

私密 `providers.json` 包含 `llm`、`embedding` 两个对象，各自提供 `model`、HTTPS `base_url`、`key_file`。`key_file` 是同目录下的普通密钥文件名。脚本只传递文件路径，不输出密钥或模型回复；验收记录仅包含用例状态、范围、耗时及私密日志摘要。供应商不可用、余额不足或模型不支持接口时会产生实际失败，不能换成模拟响应后宣称真实模型通过。

## 查看结果

各专项的 JSON 回执保存到命令输出所示的 `docs/新增需求/生产级评审/界面验证/` 或 `docs/新增需求/github作品改造/`，这些目录默认作为本地验收资料保留。新增专用脚本的原始 Go JSON 日志保存在被忽略的 `.local-secrets/test-evidence/`，不得上传。

验收时检查 `complete` 为 `true`，全部必需测试为 `pass`，且跳过、失败、缺失和清理错误均为空。将常规回归和专用回执一起评估，不能只引用一条命令的退出码。

以上五类专项使用同一个批次名（示例为 `dedicated`），全部结束后执行联合检查：

```powershell
python scripts/check_dedicated_test_results.py --inventory "docs/新增需求/github作品改造/T3-11-平台全量Go隔离PostgreSQL测试实际验证-baseline.json" --batch-id dedicated
```

联合检查逐一核对原 73 个跳过事件，校验数据库、通信及模型的私密 Go JSON 日志摘要和实际 `PASS` 事件，以及规模、进程重启的保留日志与清理结果。任一回执缺失、不完整、日志不一致、跳过或失败均返回非零退出码；只有全部通过才创建新的 73 项汇总文件。私密日志须留在本机供复核，不作为公开仓库资料。原跳过清单发生变化时必须重新审阅范围，不能强行沿用 73 项结论。

规模测试应独立执行，避免与全量编译或其他压力测试争用资源。若未达到延迟门槛，保留失败回执，使用新的批次名独立复测；不覆盖记录或降低门槛。联合检查可用 `--scale-receipt "实际复测回执的仓库路径.json"` 明确指定复测结果。该选项仍检查原规模用例、实际 PASS 日志、摘要及资源清理，并在汇总中记录实际采用的回执路径和摘要。
