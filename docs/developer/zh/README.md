# 开发者入门路线

[项目首页](../../../README.md) · [English](../en/README.md) · [日本語](../ja/README.md) · [Deutsch](../de/README.md)

目标是先理解平台和业务 Agent 的分工，再运行一个业务工程，最后把它交付给真实用户。首次阅读按下表顺序；不需要一开始就配置所有可选组件。

| 阶段 | 阅读与操作 | 完成标志 |
| --- | --- | --- |
| 认识项目 | [架构和源码地图](architecture.md) | 知道业务逻辑、身份检查、模型和知识分别由谁负责 |
| 部署基础平台 | [快速开始](quickstart.md)、[三种部署](deployment.md) | 健康检查通过，自己创建的管理员可登录 |
| 写业务代码 | [第一个 Agent](first-agent.md) | 本地业务与 SDK 生命周期测试通过，镜像可以构建 |
| 复用公共能力 | [模型、知识、工具等](capabilities.md) | 每个基础能力有明确 SDK 接入点与授权需求 |
| 交付给用户 | [发布、部署、公司与用户绑定](delivery.md) | 实际安装 active，指定用户真实运行成功，未授权用户被拒绝 |
| 后续扩展 | [二次开发](extending.md) | 变更有契约、模块边界、业务测试和迁移方案 |

如果使用代码助手，可调用[随仓库发布的 skill](skill.md)，由它围绕你的业务需求完成检查和接入。skill 不会凭空生成已通过的验收证据，也不替代你的部署环境和管理权限。

想先完整跑一次：[从空平台到用户运行自己的 Agent](walkthrough.md)提供真实部署、开发、测试、独立发布、组织授权与普通用户验收的一条命令，并说明每一步的接口、证据和临时环境清理方式。

## 先理解五个名词

| 名词 | 含义 |
| --- | --- |
| Agent Definition | 一个业务助手的稳定身份和目录信息 |
| Agent Version | 该助手的不可变版本，关联 Manifest、制品与评测 |
| Installation | 某公司 / 部门 / 内部 Application 使用某版本的安装记录 |
| Deployment | 该安装对应的实际服务端点、运行状态和部署观测 |
| Policy Snapshot | 某安装获准的模型、Prompt、工具、记忆、知识、Runtime 六类策略的发布快照 |

**镜像存在、安装存在、服务就绪、用户获准使用是四件不同的事。** 排查时先确定卡在哪一步，而不是给管理员增加全部权限。

## 按需求查找

- “`.env` 看不懂”：从[配置分层](configuration.md)的首次启动部分开始；历史参数不必配置。
- “前端没有 Agent”：按[交付流程](delivery.md)检查目录发布、安装和实际 Deployment。
- “Agent 可见但不能运行”：检查部门上限、用户使用包、机器绑定和当前策略。
- “想接自己的模型 / 工具”：先读[公共能力](capabilities.md)，再看[扩展](extending.md)。
- “打算上线集群”：读[K8s 方式](deployment.md#kubernetes-集群部署)及其尚待验收的边界。

旧的[三语言 SDK 指南](../../开发者指南/三语言SDK业务Agent开发指南.md)和[挂载与授权指南](../../开发者指南/业务Agent挂载与已有用户授权指南.md)保留为详细参考；它们包含复杂场景，不要求在入门阶段全部读完。
